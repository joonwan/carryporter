# 플로우

우선 사전에 플로우를 정하겠음

1. 사용자가 호출 요청
2. 관리자 페이지에 사물함 목록이 뜸
3. 관리자가 사물함 배정
4. 관리자가 로봇 출발 버튼 클릭(로봇 출발)
5. 로봇 이동 중 표시
6. 로봇이 사용자 위치에 도착하면 멈추고 도착 신호 보냄
7. 사용자 화면에 비밀번호 입력 화면 뜸
8. 사용자가 잠금을 해제 함(비밀번호 입력)
9. 사용자가 작업을 함 (짐 꺼내기 or 짐 싣기)
10. 사용자가 로봇을 잠금
11. 복귀 명령
12. 로봇은 복귀 중 상태
13. 로봇이 스테이션에 도착하면 관리자는 (보관 or 수령인지에 따라 달라짐) 작업을 수행하고 완료 처리

# 유저

### 1. j 단계가 없고 바로 m단계로 감

-   j단계가 있어야 함(잠금 버튼, 사용자가 직접 잠그고 버튼을 누르면 잠궜다고 서버에게 알리는 거임)
-   잠근 다음에 로봇이 바로 가는 게 아니라, 복귀 버튼을 눌러야 로봇이 스테이션으로 복귀하게 해야함

-   호출할 때 처럼 복귀할 때도 플로우가 필요함
-   정리하자면 호출 → 비번 인증으로 잠금 해제, 짐 보관(무게 측정) → 잠금 버튼 → 복귀 버튼 → 복귀 중 → 복귀 완료(여기서 관리자가 작업을 완료하면 보관 완료 화면을 출력할 지, 비동기로 미리 출력할 지 논의 필요)

### 2. 내 짐 목록 구현 안됨

### 3. 재호출 상황에서 표현이 이해가 살짝 안됨

반납 -> 확인 -> 출발을 눌러야 출발

확인 버튼은 출발 버튼이 나오기 위한 단계. 출발을 눌러야 출발

지금부터 보관과 반납이라는 개념이 없이 사용자는 로봇을 **호출**만 하는 것입니다.
호출을 하게되면 로봇이 올 것입니다.
현재 로직은 잠금버튼을 누르게 되면 바로 로봇이 출발해버리는 백엔드와 맞지 않는 로직입니다.
hotfix로 원하는 로직은 다음과 같습니다.
반납 버튼을 누르게 되면 보관이든, 반납이든 안내사항과 함께 체크사항들이 나오고 확인 버튼을 누르게 되면 출발 버튼을 활성화 할 수 있습니다. 이 출발 버튼이 바로 로봇이 출발할 수 있게 활성화하는 버튼입니다.

api 엔드포인트를 철저하게 분석하여 만들어주세요.

### 4. 스크롤 문제

-   베타테스트 결과 사용자들이 모바일에서 스크롤을 원하지 않습니다. 한 화면에 모든 내용이 담기길 바랍니다.
-   화면을 구현할 때 모바일에서 스크롤 없이 전체 내용이 다 나오게 구현해주세요.

### 5. SSE tracking 문제

-   테스트 결과 현재 SSE가 특정 메시지를 받을 때마다 색상이 변경되는 과정이 보기 좋지 않다고 합니다.
-   progress bar와 마치 진행중인 것 같은 효과를 각 단계에 넣어줘서 CSS 디자인 적으로 심미적이게 바꿔주세요.
